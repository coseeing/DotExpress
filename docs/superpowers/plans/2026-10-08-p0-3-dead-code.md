**Architecture:** Pure deletion, one deletion category per task and per commit: gui helpers, conversion text helpers, language detection, dictionary import flow module, action menu and import dialog helpers, document helpers. ## Spec Corrections (decided in this plan)

1. **Acceptance Criterion 2's focused command cannot run on Linux.** It names `tests.test_language_detection_translation`, which raises `unittest.SkipTest("liblouis bindings require WINFUNCTYPE on this platform")` at import time on non-Windows. When a module is named explicitly, `unittest`'s loader does not catch that, and the whole command aborts with a traceback before any test runs (verified on this host, Python 3.14.4; `loadTestsFromName` only turns `ImportError` into a failed test). Under `discover` the same module is reported as 1 skip. Corrected criterion: on non-Windows, run the spec's focused command without `tests.test_language_detection_translation` (expected `Ran 132 tests`, `OK`), and cover that module with `$PY -m unittest discover -s tests -p "test_language_detection*.py"` (expected `Ran 7 tests`, `OK (skipped=1)`). On Windows the spec's original command applies. (Task 7, Steps 2-3.)
2. **The test strategy leaves the `prepare_document_for_save` caller unguarded.** No existing test drives `BrailleFrame._save_open_document`. In the dry run, changing `prepare_document_for_save` to return a `Document` while leaving `gui.py:887` as `updated_document, _ = prepare_document_for_save(...)` kept the full suite green (`Ran 449`, only the P2-5 failure), yet every Save would raise `TypeError: cannot unpack non-iterable Document object` at runtime. This plan adds `test_save_open_document_saves_prepared_document` to `BrailleAppLifecycleTest` in Task 6. It passes on the current code, errors with exactly that `TypeError` once the workspace function changes, and passes again after the caller is updated. **Expected final count therefore becomes 450, not 449** (spec's arithmetic + 1). The spec explicitly allows a different arrangement as long as the count is restated.
3. **Clarifications the spec leaves implicit (not factual errors, but the counts depend on them):** the gui guard must live in `BrailleAppLifecycleTest` (the deleted `test_rename_and_delete_keep_alignment_cache_consistent` is also in that class, at line 988, so it counted once), and it must check `gui.BrailleFrame` rather than a frame instance (see Global Constraints).
4. **Hardening only:** Acceptance Criterion 3's grep walks `client/.venv` (259 MB, git-ignored). It has no matches there today, but the plan adds `--exclude-dir=.venv` so a future dependency cannot produce a false positive. The expected result is unchanged.
