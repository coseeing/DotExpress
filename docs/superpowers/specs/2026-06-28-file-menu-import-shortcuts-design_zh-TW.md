# 檔案選單與匯入快捷鍵設計

## 背景

目前 client 已經有一個文件列表的右鍵選單，負責文件生命週期相關動作：

- `Open`
- `Delete`
- `Delete All`
- `Add`
- `Rename`
- `Import`
- `Export`
- `Export All`

`Import`、`Export` 和 `Export All` 已經使用子選單來處理格式相關動作。現在的匯入流程不管從哪裡觸發，最後都會重用同一個 `on_import_document(format_key)` 處理函式。

另外，畫面設定已經提供 `Default` 和 `SimBraille` 兩種點字字型選項，但 `config.py` 內的持久化預設值仍然是 `default`，所以沒有任何 config 檔的使用者，啟動時不會直接落在 `SimBraille`。

`client/name_validation.py` 目前還有一個全域名稱長度限制 `16` 字元。這個限制會被文件名稱和字典名稱共用，所以調整它會同時影響手動新增 / 重新命名流程，以及匯入檔案名稱。

這份設計已確認的需求如下：

- 沒有 config 時，點字字型預設應該是 `SimBraille`
- 主視窗要支援 `Alt+O`，作為文件匯入 `TXT` 的直接快捷鍵
- 選單列要新增一個頂層 `檔案` / `File` 選單，內容要和文件列表右鍵選單一致
- 名稱長度限制要從 `16` 一致改成 `32`，並套用到共用的名稱驗證流程

## 目標 / 非目標

**目標：**

- 把沒有 config 時的點字字型 fallback 改成 `SimBraille`
- 新增一個視窗層級的 `Alt+O` 快捷鍵，直接打開既有的 `Import -> TXT` 流程
- 新增一個頂層 `File` 選單，提供和文件列表右鍵選單相同的文件動作與順序
- 讓新的選單列入口與既有右鍵選單在啟用 / 停用規則上保持一致
- 將共用的文件 / 字典名稱長度限制從 `16` 提升到 `32`

**非目標：**

- 不重新設計文件匯入 / 匯出邏輯
- 不變更匯入 / 匯出檔案格式
- 不另外做一套和既有處理函式分離的文件動作實作
- 不針對匯入名稱和手動輸入名稱做不同規則

## 決策

### 1. 把 `SimBraille` 設為 config 層級預設值

預設值應該改在 config 的單一真相來源，而不只是 UI 初始化時補一層 fallback。當 config 檔不存在，或 `view.braille_font` key 不存在時，`get_braille_font()` 應該回傳 `simbraille`。

這樣可以讓啟動行為、設定對話框初始化，以及未來任何呼叫端都一致，不必在 `gui.py` 裡面寫一次性的 fallback 邏輯。

### 2. `Alt+O` 直接綁到既有的 TXT 匯入處理函式

`Alt+O` 不應該只是打開選單或切換焦點。它應該要和文件列表右鍵選單的 `Import -> TXT` 走同一條流程，也就是最後會呼叫既有的文件匯入處理函式，並帶入 `format_key="txt"`。

這符合已確認的使用者意圖：在整個視窗內按下 `Alt+O` 就要立即開始 TXT 匯入。

### 3. 新增一個和文件列表動作鏡像的頂層 `File` 選單

選單列應該新增一個頂層 `File` 選單，放在現有頂層選單之前或旁邊。它的項目順序要和文件列表右鍵選單完全一致：

- `Open`
- `Delete`
- `Delete All`
- `Add`
- `Rename`
- `Import`
- `Export`
- `Export All`

`Import`、`Export` 和 `Export All` 應該保留和既有右鍵選單相同的子選單結構與格式選項：

- `Import` -> `DEP`, `TXT`
- `Export` -> `DEP`, `BRL`
- `Export All` -> `DEP`, `BRL`

新的頂層選單只是同一組文件命令的另一個入口，不是新的工作流程。

### 4. 文件列選單定義共用一份

動作順序、子選單格式標籤，以及事件綁定都應該來自同一份共用定義，而不是在兩個地方各寫一份。

這可以避免一個很容易發生的問題：文件列表右鍵選單和頂層 `File` 選單之後慢慢長得不一樣。

這份共用定義應該負責：

- 項目順序
- 子選單結構
- 處理函式綁定
- 依目前選取狀態與文件存在與否決定啟用 / 停用

### 5. 將共用名稱長度限制從 `16` 改成 `32`

名稱長度的單一真相來源就是共用的名稱驗證常數，所以限制應該直接改那裡。因為文件與字典的命名都已經依賴同一條路徑，所以新的行為應該一致套用到：

- 由檔案 stem 推導出的匯入文件名稱
- 手動新增的文件名稱
- 重新命名後的文件名稱
- 手動新增的字典名稱
- 重新命名後的字典名稱
- 匯入後的字典名稱

所有現在還寫著 `1 to 16 characters` 的使用者可見驗證訊息，都要改成 `1 to 32 characters`。

這是最乾淨的作法，因為它保留單一命名規則，而不是另外做一個只對匯入有效的特例。

## UI / 行為

### 點字字型預設

- 沒有 config 檔時，或 `view.braille_font` 缺少時，實際生效的點字字型都應該是 `simbraille`
- 已經存在的持久化值要維持原本行為
- 無效的持久化值仍然要走既有的正規化 fallback，只是現在會落到 `simbraille`

### `Alt+O`

- 不管目前焦點在主視窗哪個子控制項上，都要能觸發
- 會打開和 `on_import_document("txt")` 相同的檔案選擇與匯入流程
- 不需要先把焦點切到文件列表
- 不會先打開 `File` 選單作為中介步驟

### 頂層 `File` 選單

- 項目順序和文件列表右鍵選單一致
- 匯入 / 匯出動作使用相同的子選單格式
- 啟用 / 停用規則和既有右鍵選單一致
- 除了專用的 `Alt+O` 之外，也能透過一般選單列鍵盤操作進入

## 風險 / 取捨

- 多一個文件動作入口會增加狀態分歧的風險
  - 緩解方式：集中管理選單結構與綁定資料，不要維護兩套獨立實作
- 改變共用名稱長度會同時影響文件與字典流程，不只匯入
  - 這是接受的取捨，因為確認過的需求就是要全域一致，而且現有程式本來就把名稱長度視為共用限制
- `SimBraille` 當預設值，在某些平台上可能會遇到執行期字型註冊的限制
  - 可接受，因為這個需求只在處理沒有 config 時的預設值；既有的字型套用 fallback 行為應該保持不變

## 測試

驗證應該包含：

- `get_braille_font()` 在 config 缺失時回傳 `simbraille`
- 已存在的 `braille_font` 持久化值仍然能正常 round-trip
- 主選單列包含一個頂層 `File` 選單，且項目順序正確
- `File > Import > TXT` 走到和文件列表右鍵選單相同的處理函式路徑
- `Alt+O` 在不需要文件列表焦點的情況下也能從主視窗觸發 TXT 匯入
- 頂層 `File` 選單的啟用 / 停用規則和既有文件列表右鍵選單一致
- 文件名稱驗證可以接受最多 `32` 字元，超過 `33` 字元則拒絕
- 字典名稱驗證可以接受最多 `32` 字元，超過 `33` 字元則拒絕
- 匯入的 TXT / DEP 檔案 stem 長度到 `32` 字元仍可成功載入
- 現有測試中任何把限制寫死為 `16` 字元的地方，都要改成 `32`

## 實作大綱

1. 把 config 層級的點字字型預設 key 從 `default` 改成 `simbraille`。
2. 新增一個共用的文件選單描述 / helper，讓文件列表右鍵選單和頂層 `File` 選單都能用。
3. 把頂層 `File` 選單加到 frame 的選單列，並接到既有的文件處理函式。
4. 加上 frame 層級的 accelerator 或等效鍵盤綁定，讓 `Alt+O` 直接觸發 TXT 匯入。
5. 把共用名稱長度限制從 `16` 提升到 `32`，並同步更新相關驗證文字。
6. 更新單元測試，涵蓋 config fallback、文件選單結構、快捷鍵觸發，以及新的 `32` 字元名稱限制。
