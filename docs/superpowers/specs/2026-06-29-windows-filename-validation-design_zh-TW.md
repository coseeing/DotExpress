# 文件與字典的 Windows 檔名驗證

## 摘要

將文件與字典的命名規則調整為符合 Windows 合法檔名規則，而不是目前這個會禁止 `.` 的自訂限制。如此一來，像 `1.1` 這類名稱就能在整個應用程式中一致地建立、匯入、儲存、顯示與重新命名。

同時，調整字典匯入流程，讓使用者在選取 CSV 檔後，不會直接把檔名主體當成最終字典名稱。檔案選取後，應開啟既有的字典名稱對話框，並預先填入檔名主體，讓使用者可以在匯入前接受或修改名稱。若取消這個對話框，匯入就必須中止，且不得複製任何檔案。

## 目前狀態

- 共用的名稱驗證集中在 [client/name_validation.py](/workspace/DotExpress/client/name_validation.py)。
- 文件與字典的命名都會經過這個共用驗證。
- 目前的非法字元規則會禁止 `.`, `/` 和 `\`，所以像 `1.1` 這種名稱雖然是有效的 Windows 檔名，卻仍會被拒絕。
- 文件文字匯入已經會從 `Path(...).stem` 取得候選名稱，所以 `1.1.txt` 會自然得到 `1.1`；失敗點是在驗證，不是在擷取檔名主體。
- 字典匯入目前雖然也是先讓使用者輸入名稱，但不會預先填入選到的檔名主體，因此沒有達到「先確認再匯入」的流程。

## 目標

- 允許文件與字典使用 Windows 合法檔名。
- 文件與字典共用同一套驗證規則。
- 保留現有 DEP 封包格式與工作區行為。
- 讓字典匯入使用和手動新增字典相同的命名與重名處理流程。

## 非目標

- 不變更 `.dep` 封包格式。
- 不變更工作區排序行為。
- 不移除現有的 32 字元限制。
- 不為非 Windows 主機加入平台分支行為。

## 命名規則

`normalize_base_name()` 仍然是唯一的驗證入口。它的行為會從簡單的黑名單檢查，改為 Windows 檔名合法性檢查。

允許的例子：

- `1.1`
- `chapter.2`
- `ver 2.0`

拒絕的例子：

- 空字串或只有空白的名稱
- `.`
- `..`
- 以 `.` 或空白結尾的名稱
- 含有 `<`, `>`, `:`, `"`, `/`, `\`, `|`, `?`, `*` 的名稱
- 含有控制字元的名稱
- Windows 保留裝置名稱，例如 `CON`, `PRN`, `AUX`, `NUL`, `COM1` 到 `COM9`，以及 `LPT1` 到 `LPT9`
- 長度超過 32 字元的名稱

正規化仍然以去除前後空白為主。去除空白後的名稱仍必須符合上述 Windows 合法性規則。

## 文件

不需要變更封包格式。

- 工作區檔案仍會儲存為 `<document_name>.dep`
- DEP 內容仍會儲存為 `<document_name>.txt` 與 `<document_name>.brl`
- 文字匯入仍會從 `Path(source).stem` 擷取基礎名稱
- DEP 載入仍會比對封包主體名稱與內部 `.txt`、`.brl` 的主體名稱

由於 Python 的 `Path.stem` 會把 `1.1.txt` 正確視為 `1.1`，只要允許驗證後的文件名稱中包含 `.`，就足以修正目前這個匯入失敗的案例。

## 字典

字典名稱會改為與文件相同的 Windows 合法共用規則。

字典匯入流程會改成：

1. 使用者選取一個 CSV 檔。
2. 程式從 `source_path.stem` 取得預設名稱。
3. 程式開啟 `DictionaryNameDialog`，並把這個名稱預先填入可編輯文字欄位。
4. 使用者可以直接接受建議名稱，也可以自行修改。
5. 按下 OK 後，程式使用對話框中的最終名稱進行驗證與匯入。
6. 按下 Cancel 後，匯入中止，且不會複製任何檔案。

這樣可以讓匯入的字典和手動建立的字典維持一致，也能在預設名稱與既有名稱衝突時，讓使用者直接在同一個流程內修正。

## 錯誤處理

- 共用驗證失敗仍然會從正規化層丟出 `ValueError`。
- UI 入口仍然會把這些錯誤轉成對使用者可見的訊息視窗。
- 字典名稱重複仍然沿用既有的重名錯誤處理流程。
- 無效的 CSV 結構仍然沿用既有的標頭驗證錯誤處理流程。
- 取消檔名對話框會被視為正常的無操作，不算錯誤。

## UI 變更

- `DocumentNameDialog` 的文件名稱驗證說明不能再宣稱 `.` 被禁止。
- `DictionaryNameDialog` 的字典名稱驗證說明不能再宣稱 `.` 被禁止。
- `DictionaryNameDialog` 應支援接收初始值，讓匯入時可以預先填入選到的檔名主體，而重新命名時則仍可預先帶入目前名稱。

## 測試

需要新增或更新以下測試：

- `normalize_document_name("1.1")` 會成功。
- `normalize_dictionary_name("1.1")` 會成功。
- `.`, `..`, `name.` 與 `name ` 會被拒絕。
- 像 `CON` 與 `LPT1` 這類保留裝置名稱會被拒絕。
- 無效的 Windows 字元會被拒絕。
- `1.1.txt` 的文件匯入會成功，且產生文件名稱 `1.1`。
- 字典匯入對話框流程會先預填選到的檔名主體，且能在取消時乾淨地中止匯入。

## 風險與緩解

- 共用規則變更會同時影響文件與字典。
  緩解方式：保留兩條路徑的測試，避免再另外藏任何例外規則。
- Windows 檔名語意包含比原本黑名單更多的邊界情況。
  緩解方式：在 `name_validation.py` 中明確實作合法性規則，並用精準的單元測試驗證。
- UI 文字可能與實際驗證行為脫節。
  緩解方式：在修改驗證邏輯的同一次變更中，一併更新兩個對話框的驗證說明。
