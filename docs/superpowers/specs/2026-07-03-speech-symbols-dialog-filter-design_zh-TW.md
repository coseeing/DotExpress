# 語音符號對話框篩選功能設計

## 摘要

這項變更會為 DotExpress 的自訂字典編輯對話框 [SpeechSymbolsDialog](/workspace/DotExpress/client/dialog.py) 新增比照 NVDA 的篩選功能。目前這個對話框使用一般的 `wx.ListCtrl` 顯示所有字典條目，尚未提供搜尋或篩選能力。新的設計會加入即時篩選文字輸入框，並將清單升級為 virtual list，使對話框在字典條目數量達數百到上千筆時仍能維持良好回應。

篩選行為應盡量參考 `include/nvda/source/gui/settingsDialogs.py` 中 NVDA 的 `SpeechSymbolsDialog`，但需配合 DotExpress 的資料模型調整。篩選僅作用於 `Source Text` 與 `Braille` 欄位。`Type` 仍會顯示，但不納入搜尋條件。

## 目標

- 在 `SpeechSymbolsDialog` 中新增即時篩選文字輸入框。
- 僅依 `Source Text` 與 `Braille` 篩選條目。
- 篩選比對採不分大小寫。
- 使用 virtual `wx.ListCtrl`，讓對話框能支援數百到上千筆條目。
- 在篩選條件改變時，儘可能保留原本選取的項目。
- 當篩選結果為空時，停用 `Edit` 與 `Delete`。
- 讓新增、編輯、刪除與儲存流程在有無篩選狀態下都維持一致。
- 在適合的範圍內重用 NVDA 的互動模式。

## 非目標

- 不支援依 `Type` 篩選。
- 不加入進階搜尋語法、正規表示式或多欄位搜尋選項。
- 這次變更不加入排序 UI。
- 不重新設計 `AddSymbolDialog`。
- 不變更 CSV 儲存格式。

## 使用者可見行為

### 篩選輸入框

- 在條目清單上方新增一個文字輸入框。
- 使用者輸入時，清單會立即套用篩選結果。
- 篩選字串為空時，顯示完整字典。
- 比對採不分大小寫。
- 當篩選文字包含於以下任一欄位時，該列視為符合：
  - 條目的 `Source Text`
  - 條目的 `Braille`

### 篩選後的清單行為

- 條目清單仍維持單選。
- 對話框應在重新篩選後，盡可能保留先前選取的條目。
- 若先前選取的條目已不在篩選結果中，則選取目前可見的第一列。
- 若篩選結果為空：
  - 不選取任何列
  - 停用 `Edit`
  - 停用 `Delete`
  - 不顯示任何資訊或警告提示

### 新增行為

- 新增條目仍透過 `AddSymbolDialog` 進行。
- `Source Text` 重複檢查維持現有行為不變。
- 若新條目符合目前篩選條件：
  - 保留目前的篩選文字
  - 顯示目前的篩選結果
  - 選取新條目
- 若新條目不符合目前篩選條件：
  - 清空篩選文字
  - 顯示完整清單
  - 選取新條目

### 編輯行為

- 編輯仍作用於目前選取且可見的列。
- 編輯確認後，對話框會重新套用目前篩選條件。
- 若編輯後的條目仍符合篩選條件，則保持選取。
- 若編輯後的條目不再符合篩選條件，它會自然從篩選清單中消失，選取則回落到鄰近可見列或第一列。

### 刪除行為

- 刪除仍作用於目前選取且可見的列。
- 刪除後，對話框會重新套用目前篩選條件。
- 若仍有可見列，選取移到最接近的剩餘列。
- 若已無可見列，則停用 `Edit` 與 `Delete`。

## 內部設計

### 資料模型

`SpeechSymbolsDialog` 應維護兩個集合：

- `self.entries`
  - 完整的字典條目清單
  - 作為儲存操作的真實資料來源
- `self.filtered_entries`
  - 套用篩選後目前可見的條目清單
  - 其角色對應 NVDA 的 `filteredSymbols`

此設計應沿用既有的 `DictionaryEntry` dataclass，不另行引入第二套持久化資料模型。

### 清單控制項

將目前直接重新填入資料的一般清單流程，改為 virtual report list：

- style 應包含：
  - `wx.LC_REPORT`
  - `wx.LC_SINGLE_SEL`
  - `wx.LC_VIRTUAL`
- 清單列文字應動態由 `self.filtered_entries` 提供
- 欄位配置維持：
  - `Source Text`
  - `Braille`
  - `Type`

之所以採用此方式，是因為這次的設計目標是支援數百到上千筆資料；在這種規模下，反覆刪除並重建整個清單已不夠合適。

### 篩選方法

新增專責方法，例如 `filter_entries(filter_text: str = "") -> None`。

此方法應：

- 先記住目前選取且可見的條目（若有）
- 計算 `self.filtered_entries`
  - 若 `filter_text` 為空，顯示全部條目
  - 否則僅保留 `text` 或 `braille` 包含篩選字串的條目，且比對不分大小寫
- 更新 virtual list 的 item count
- 若先前選取的條目仍可見，恢復其選取狀態
- 否則選取目前可見的第一列
- 若篩選結果為空，清除選取並停用編輯/刪除控制項

實作上應盡可能貼近 NVDA 的 `filter()` 互動模式，但維持 DotExpress 可接受的結構與依賴。

### 選取狀態追蹤

選取邏輯應以條目本身為基準，而不是以原始索引為基準。

對話框應在重新篩選前先記住目前選取的 `DictionaryEntry` 物件，再於重新計算後的 `self.filtered_entries` 中尋找同一個物件，若仍可見則恢復選取。

這樣可避免 virtual list 的索引在篩選、編輯或刪除後改變，導致選錯列。

### 項目文字提供方式

清單應透過單一路徑提供顯示文字，其角色等同 NVDA 的 `getItemTextForList`。

對每一列可見項目：

- 第 0 欄回傳 `entry.text`
- 第 1 欄回傳 `entry.braille`
- 第 2 欄回傳 `entry.entry_type` 的在地化顯示標籤

### 新增 / 編輯 / 刪除整合

所有列操作都應先針對 `self.filtered_entries` 中目前選取的條目，再回寫到 `self.entries`，最後重新套用目前篩選條件。

建議流程如下：

- 新增
  - 驗證 `Source Text` 是否重複
  - 將新條目加入 `self.entries`
  - 若新列符合目前篩選條件，保留篩選
  - 若不符合，清空篩選輸入框並顯示全部列
  - 選取新列
- 編輯
  - 以 `self.filtered_entries` 中目前選取的條目開啟編輯
  - 驗證 `Source Text` 是否重複，但排除同一筆原始條目
  - 在 `self.entries` 中更新對應條目
  - 重新套用目前篩選條件
  - 若編輯後條目仍可見，嘗試重新選取
- 刪除
  - 自 `self.entries` 移除目前選取條目
  - 重新套用目前篩選條件
  - 選取最接近的剩餘列

### 按鈕狀態規則

`Edit` 與 `Delete` 的啟用狀態必須由可見清單中的選取狀態決定。

- 若目前有可見列被選取，啟用兩者。
- 若目前沒有可見列被選取，停用兩者。
- 篩選到零筆可見列時，必須直接停用兩者，不顯示提示。

### 儲存行為

儲存仍應以 `self.entries` 為基礎，而不是 `self.filtered_entries`。

這可確保即使某些條目目前被篩掉未顯示，仍會完整保留並正確寫回磁碟。

## 測試

### 對話框層級測試

為 `SpeechSymbolsDialog` 新增聚焦測試，涵蓋：

- 空篩選字串時顯示全部條目
- 可依 `Source Text` 篩選
- 可依 `Braille` 篩選
- 篩選比對不分大小寫
- 不可依 `Type` 篩選
- 篩選結果為空時會停用 `Edit` 與 `Delete`
- 當原本選取的條目仍可見時，選取能被保留
- 當原本選取的條目被篩掉時，選取能正確回落

### 操作流程測試

新增測試涵蓋：

- 新增符合目前篩選條件的條目時，保留篩選並選取新列
- 新增不符合目前篩選條件的條目時，清空篩選並選取新列
- 編輯條目後若仍符合篩選，能維持可見並保留選取
- 編輯條目後若不再符合篩選，會自可見列中移除
- 刪除目前選取的篩選列後，選取會移到最近的剩餘列
- 儲存時會寫出完整條目，而不只是目前篩選後可見的條目

### 回歸測試涵蓋範圍

既有驗證行為應維持不變，包括：

- `Source Text` 重複檢查
- 無效 Bopomofo 輸入
- 無效 Unicode braille 輸入
- 儲存失敗的錯誤處理

## 風險與限制

- `wx.ListCtrl` 的 virtual mode 會改變列文字提供方式與選取狀態管理方式，這是主要實作風險。
- 目前測試套件多使用輕量 wx stub，因此測試應聚焦於對話框邏輯與受控清單互動，而不是深入驗證原生 GUI 行為。
- 條目物件的識別性必須在篩選與編輯流程中足夠穩定，才能正確保留選取狀態。
- 實作應盡量貼近 NVDA 的模型，但不應直接搬用 DotExpress 內不存在的 NVDA 專屬控制項或 helper 基礎設施。

## 驗收標準

- `SpeechSymbolsDialog` 在條目清單上方包含一個篩選輸入框。
- 使用者輸入時，清單會立即更新。
- 篩選僅檢查 `Source Text` 與 `Braille`。
- 篩選比對不分大小寫。
- 條目清單使用適合大型字典的 virtual list 行為。
- 當篩選結果為空時，`Edit` 與 `Delete` 會被停用，且不顯示任何提示。
- 新增不符合目前篩選條件的條目時，會清空篩選並選取新條目。
- 新增符合目前篩選條件的條目時，會保留篩選並選取新條目。
- 在篩選狀態下，編輯與刪除仍能正確運作。
- 儲存時仍會寫出完整字典，而不只是目前可見條目。
