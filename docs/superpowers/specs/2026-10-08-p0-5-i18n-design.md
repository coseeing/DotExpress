# Shared i18n Module (P0-5) Design

## Goal

Give the client one place that sets up translations and finds bundled resources: a new `client/i18n.py` that provides `_`, `N_` and `resource_path`. Every module that today builds its own `gettext` catalog or its own `resource_path()` imports from it instead. This is roadmap task P0-5 (`storage/refactor.md` section 6.1, finding "gettext 初始化 + `resource_path()` 複製 5 份" in section 5).

Scope: the five first-party copies the roadmap row names. The NVDA-derived `client/braille/tables/__tables.py` also has a copy, but it is excluded by decision and stays untouched (see "Known issues / follow-ups").

What changes for users: nothing, whether the app runs packaged or from source. Every string keeps the same zh_TW translation, and every resource path stays the same. The msgid set that `scripts\generate-pot.bat` extracts stays the same.

Revision: corrected after planning (`docs/superpowers/plans/2026-10-08-p0-5-i18n.md`, "Spec Corrections and Refinements"): 16 `test_i18n` cases instead of about 9, seven commits instead of three, the guard test uses the criterion 1 pattern (including `LOCALE_LANGUAGES`), `load_translation` tests `localedir is None`, and the list of `gui._` call sites in `test_gui_document_flows.py` is complete.

### Findings

- **The `parents[1]` difference is a depth fix, not a different root.** `settings/dialogs.py` and `dictionaries/entries.py` sit one directory below `client/`, so `parents[1]` and `gui.py`'s `parent` both point at `client/`. One `resource_path` anchored at `client/i18n.py` removes the need for it.
- **Frozen builds.** `scripts/build-dotexpress.bat` runs `pyinstaller --onefile ... --add-data "locales;locales" --add-data "data;data" ... gui.py`. Three sites check `sys._MEIPASS` explicitly. `about.py` and `dictionaries/entries.py` do not, but they still find the catalog in the packaged app. PyInstaller sets `__file__` of a module bundled in the PYZ archive to `sys._MEIPASS/<package path>.pyc`, so `Path(__file__).resolve().parent` (or `parents[1]`) already equals `_MEIPASS`. In a frozen build both bases agree. `i18n.py` keeps the explicit `_MEIPASS` branch, which is the documented PyInstaller way and the one most sites use.
- **Latent bug in `__tables.py` (not fixed here).** Its `resource_path` goes up only to `client/braille/`. From source, the catalog lookup fails silently (`fallback=True`), so every `BrailleTable.displayName` stays English. Checked: `resource_path("locales")` is `/workspace/DotExpress/client/braille/locales`, which does not exist, and `listTables()[0].displayName` is `'Afrikaans grade 1'`. In the frozen build the `_MEIPASS` branch finds the catalog, so the names are Chinese (`'南非文一級'`). The only consumer is `settings/dialogs.py:623-625`, which calls `_(table.displayName)` again. The names shown in the settings dialog are therefore Chinese in both modes. `listTables()` sorts by `strxfrm(displayName)`, though, so the order of the 196 output tables differs between source runs (English order) and the packaged app (order of the translated names).
- **No builtins `_`.** Nothing calls `gettext.install()` or sets `builtins._` (`builtins` shows up only in `tests/test_main_demo.py` patching `print`, and in the NVDA submodule). Every module uses a module-global `_`.
- **How tests use `_`.** `tests/test_dialog_display.py` (lines 45-50, 60-65, 76-85) swaps `dialog_module._` for a dict's `.get` and restores it. That works because the functions look up the module global `_` when they are called. `tests/test_gui_document_flows.py` calls `gui._("...")` to build expected strings (207, 230-231, 296-300, 412-413, 463, 493-494, 768, 826-827, 944-945, 1014). `tests/test_dialog_validation.py` asserts real zh_TW messages from `dialog.py`. `tests/test_config.py` and `tests/test_import_fixtures.py` open the `.mo` file directly with `gettext`, without going through any module. No test reads or patches `resource_path`, `LOCALE_DOMAIN`, `LOCALE_LANGUAGES` or `_translation` on any module.
- **`N_` does not exist yet.** `gui.py:167-217` keeps `_MENU_TRANSLATION_MARKERS`, a tuple of 48 `_("...")` calls whose only job is to let `xgettext` see labels that are translated dynamically elsewhere (menu labels from `ui/action_menu.py`, file wildcards and others). Nothing reads the tuple.
- **Extraction script.** The file is `scripts/generate-pot.bat` (hyphen). `AGENTS.md`, `readme.md` and older plans call it `generate_pot.bat`. It runs `xgettext --language=Python --keyword=_ --files-from=<all client *.py except .venv and tests> --output=locales\dotexpress.pot`. `N_` is not one of xgettext's default Python keywords, so it has to be added explicitly.
- **Other `__file__`-based paths** (`app_paths.get_application_root`, the executable directory for writable data; `conversion/mathcat_adapter.py:17`, MathCAT assets; `main.py` `BASE_DIR`, demo only) have nothing to do with gettext and are out of scope (see "Out of scope").

### `StubScope` interaction (P0-4)

`i18n.py` imports only the standard library (`gettext`, `sys`, `pathlib`). It never references `wx`, so the `StubScope` leak guard (R4) cannot fire on it, and it does not need to be in any `isolate` list. Depending on the scope's eviction policy it may be imported inside a scope and stay cached (`evict_nothing`, speech roots) or be evicted afterwards (`evict_everything` in `load_display_dialog`). Eviction is harmless: the loaded module keeps the bound `_` it imported, and a later import builds an equivalent catalog from the same files. No test may depend on `i18n` module identity across test modules.

## Design

### Decision: one stateless module, consumers bind `_` at import

Alternatives considered:

1. **`gettext.install()` (builtins `_`), like NVDA.** Rejected. It hides missing imports, makes `_` global state for the whole process (tests that swap `dialog_module._` would have to patch `builtins` instead), and changes how every module resolves `_`.
2. **Consumers call `i18n._(...)` through the module.** Rejected. xgettext would no longer see `_(` at the call sites (the keyword would need to be `i18n._`), and tests that patch `<module>._` would stop working.
3. **Chosen: `from i18n import _` (and `N_`, `resource_path` where used).** Each consumer keeps a module-global `_` that is the same bound method as `i18n._`. Call sites, xgettext keywords, and the existing `dialog_module._` / `gui._` test patterns all stay as they are.

### `client/i18n.py`

4-space indentation (new file, per `AGENTS.md`), ASCII, standard library only. The names are the contract. The plan may adjust only private details.

```python
LOCALE_DOMAIN = "dotexpress"
LOCALE_LANGUAGES = ("zh_TW",)
CLIENT_ROOT = Path(__file__).resolve().parent

def resource_path(relative_path: str) -> Path:
    # frozen (PyInstaller): Path(sys._MEIPASS) / relative_path
    # otherwise:            CLIENT_ROOT / relative_path
    ...

def load_translation(localedir: Path | None = None,
                     languages: Sequence[str] = LOCALE_LANGUAGES) -> gettext.NullTranslations:
    # if localedir is None: localedir = resource_path("locales")
    # gettext.translation(LOCALE_DOMAIN, localedir=str(localedir),
    #                     languages=list(languages), fallback=True)
    ...

_translation = load_translation()
_ = _translation.gettext

def N_(message: str) -> str:
    """Mark a string for extraction without translating it."""
    return message
```

- **`resource_path`** keeps the current rule exactly: `_MEIPASS` only when `getattr(sys, "frozen", False)` **and** `hasattr(sys, "_MEIPASS")`, otherwise the directory that contains `i18n.py` (`client/` from source, `_MEIPASS` when frozen, as discussed above). The check runs at **call time**, so tests can patch `sys.frozen`/`sys._MEIPASS` with `patch.object(sys, ..., create=True)`.
- **Import time.** The catalog is loaded once, when `i18n` is first imported, from `resource_path("locales")` evaluated at that moment. This matches today: every site loads at import, and PyInstaller sets `sys.frozen`/`_MEIPASS` before any application code runs. Module-level translated constants in consumers (`ENTRY_TYPE_OPTIONS`, `about.aboutMessage`) are still evaluated when those modules are imported, so the order of evaluation does not change.
- **Language.** Fixed `("zh_TW",)` with `fallback=True`, as today. It does not follow `LANG`/`LANGUAGE`. A missing or unreadable catalog never raises; `_` then returns the msgid. Making the UI language configurable is out of scope.
- **`load_translation`** is public so tests can exercise the fallback path with a temporary directory. Production code calls it only once, inside `i18n`.
- **Patching rule.** Tests keep patching the consumer's global (`dialog_module._ = ...`). Patching `i18n._` after a consumer imported it has no effect on that consumer. The module docstring says so.
- **No `ngettext`/`pgettext`**, because nothing uses them (YAGNI). No `__all__`, because consumers import names explicitly.

### `N_` and `scripts/generate-pot.bat`

- `scripts/generate-pot.bat`: change `--keyword=_` to `--keyword=_ --keyword=N_`. Nothing else changes (file list, output path, no `--from-code`, no `--add-comments`).
- `gui.py`: the 48 entries of `_MENU_TRANSLATION_MARKERS` change from `_("...")` to `N_("...")`. The tuple stays in `gui.py` with its comment. Moving the markers next to the labels in `ui/action_menu.py` belongs to O-1 / P1-2 (action-keyed menus), not here. The tuple's value becomes the untranslated strings, and nothing reads it. This gives `N_` a real caller in the same commit that adds the keyword, so neither change exists without the other.
- **What "the .pot stays the same" means.** The extracted **msgid set** (and therefore every msgid/msgstr pair in `dotexpress.po`) is identical: the AST scan with keywords `_` and `N_` gives the same 357 strings before and after. xgettext decides format flags (`python-format`, `python-brace-format`) from the string content, whatever the keyword, so the flags stay the same too. The `#:` source references and `POT-Creation-Date` **will** change when the script is next run (line numbers shift in every migrated file). As in P0-2, this task does not hand-edit `dotexpress.pot`, `dotexpress.po` or the `.mo`. The references refresh on the next Windows run of `generate-pot.bat`.

### Per-module migration

Each consumer deletes its `resource_path`/`_resource_path`, `LOCALE_DOMAIN`, `LOCALE_LANGUAGES`, `_translation` and `_ = ...`, plus any import that becomes unused (`gettext`, and `sys`/`Path` only where nothing else uses them). It then adds the `i18n` import with its other first-party imports. Indentation stays per file.

| Module | Imports from `i18n` | Imports that become unused | Notes |
| --- | --- | --- | --- |
| `gui.py` | `_`, `N_`, `resource_path` | `gettext` (`sys` and `Path` are still used) | `gui._` and `gui.resource_path` stay module attributes, which `test_gui_document_flows` relies on for `gui._`. Markers switch to `N_`. |
| `dialog.py` | `_` | `gettext`, `sys` (`Path` still used at 429, 690) | `dialog.resource_path` disappears. No caller outside the module (checked). |
| `settings/dialogs.py` | `_` | `gettext`, `sys` (`Path` still used at 131) | The `parents[1]` quirk goes away. `_(table.displayName)` at 625 stays (see below). |
| `dictionaries/entries.py` | `_` | `gettext` (`Path` still used in signatures) | Gains `_MEIPASS` handling by delegation. Same result in the packaged app. |
| `about.py` | `_` | `gettext`, `Path` | `about` is also imported by `client_init.py`. `i18n` adds no dependency beyond the standard library. |

`i18n` imports nothing from the client, so the change cannot create an import cycle.

`client/braille/tables/__tables.py` is not migrated (see Scope). Its gettext block, its `resource_path` and its lookup through the nonexistent `client/braille/locales` stay exactly as they are. That is why no behavior changes, not even in source runs.

## Test Strategy

New `client/tests/test_i18n.py` (4 spaces, `unittest`, no `wx`, so it needs no `StubScope`). 16 cases:

1. `resource_path` without `frozen` returns `<client>/<relative>`, and `resource_path("locales") / "zh_TW" / "LC_MESSAGES" / "dotexpress.mo"` exists.
2. With `sys.frozen = True` and `sys._MEIPASS = <tmp>` (patched with `create=True`), it returns `<tmp>/<relative>`.
3. With `sys.frozen = True` and no `_MEIPASS`, it falls back to the client root (the current `and hasattr` rule).
4. `_("General") == "一般"` and `_("Startup Error") == "啟動錯誤"` (msgids already pinned by `test_config`). The same case pins `LOCALE_DOMAIN == "dotexpress"`, `LOCALE_LANGUAGES == ("zh_TW",)` and that `load_translation()` returns a `GNUTranslations`.
5. An unknown msgid comes back unchanged.
6. `load_translation(localedir=<empty tmp dir>)` returns a `NullTranslations` whose `gettext` is the identity function, and does not raise.
7. `N_(s)` returns the same object `s`, including for a msgid that has a translation (`N_("General") == "General"`).
8. The language does not follow the environment: a subprocess with `cwd=client/`, `LANGUAGE=en_US`, `LANG=C` and `LC_ALL=C` runs `from i18n import _; print(_("General"))` and gets `一般` (UTF-8 output forced with `PYTHONIOENCODING`).
9. No duplicated setup (`DuplicateSetupGuardTest`): a static scan of `client/**/*.py` finds no match of the criterion 1 pattern `gettext\.translation\(|^\s*import gettext|_MEIPASS|def _?resource_path|LOCALE_LANGUAGES`. It prunes directories named `tests`, `.venv` or `__pycache__` at any depth (as `generate-pot.bat` filters `\tests\` and `\.venv\` anywhere) and skips `i18n.py` and the out-of-scope `braille/tables/__tables.py`. It fails until every migration has landed, so it lands with the `gui.py` migration.
10. `dialog.py` imports `{"_"}` from `i18n` and keeps none of the old setup (`SharedSetupConsumerTest.test_dialog_uses_shared_i18n`).
11. The same for `settings/dialogs.py`.
12. The same for `dictionaries/entries.py`.
13. The same for `about.py`.
14. The same for `gui.py`, which imports `{"N_", "_", "resource_path"}` (`{"_", "resource_path"}` until the `N_` commit).

Cases 10-14 parse the module with `ast` (no import, so no `wx` and no `StubScope`) and check that it imports exactly the expected names from `i18n`, has no `import gettext`, defines no top-level `resource_path`/`_resource_path`, and assigns no top-level `LOCALE_DOMAIN`, `LOCALE_LANGUAGES`, `_translation` or `_`. Each lands with its module's migration and fails before it.

15. All 48 `_MENU_TRANSLATION_MARKERS` entries in `gui.py` are `N_(...)` calls (AST check).
16. `scripts/generate-pot.bat` runs `xgettext --language=Python --keyword=_ --keyword=N_ --files-from=...`.

Existing tests are the safety net and must not be edited: `test_dialog_validation` (real zh_TW messages through `dialog._`), `test_dialog_display` (swaps `dialog_module._`), `test_gui_document_flows` (`gui._`), `test_settings_dialogs`, `test_speech_symbols_dialog`, `test_dictionary_management_dialog`, `test_dual_view_frame`, `test_wx_stub`, `test_config`, `test_client_init`, `test_import_fixtures`.

Extraction cannot be run here (no `xgettext`). The AST scan from the Method section stands in for it: same keywords (`_`, `N_`), same file set as `generate-pot.bat`. Run it before and after, and expect identical sets of 357 msgids, both equal to the `.pot` msgid set.

- **Packaged path resolution** (low, cannot be verified here). The frozen branch is unchanged for `gui.py`, `dialog.py` and `settings/dialogs.py` (and `__tables.py` is not touched). For `about.py` and `dictionaries/entries.py` it replaces a `__file__`-based path that already resolves to `_MEIPASS` under PyInstaller 6.21. PyInstaller finds `i18n` by static import analysis from `gui.py`, so no hidden-import entry is needed. Verify on Windows (criterion 10).
- **Extraction with `N_`** (low, cannot be verified here). If someone runs an old copy of the extraction command without `--keyword=N_`, the strings that appear only in the marker tuple drop out of the `.pot` (for example the menu labels "Add", "Edit", "Delete" and "Package DEP"). The keyword and the markers change in the same commit, and criterion 10 checks the result.
- **Test patching semantics** (low). Patching `i18n._` does not reach modules that already imported `_`. No test does this today. The `i18n` docstring and `test_i18n` document the rule: patch the consumer's `_`.
- **`StubScope` eviction** (low). `i18n` may be evicted and re-imported between test modules. That only rebuilds an identical catalog. Criterion 6 covers it.
- **Name collision** (low). No installed distribution provides a top-level `i18n` (the `find_spec("i18n")` check in the venv gives `None`), `client/` comes first on `sys.path` when running from source, and PyInstaller resolves `i18n` from `client/` (the script's directory) when it builds the bundle.
